- external: AppKit objects such as NSWindow, NSScreen and view frames may only be touched on the main thread, while Kodi's render and app loop run on another. CWinSystemOSX wraps such access in dispatch_sync to the main queue; direct reads crash during live resize and moves. | check: macOS windowing code touching NSWindow, NSScreen or view state from Kodi threads hops to the main queue, and never dispatch_syncs to the main queue from the main thread itself | at: `xbmc/windowing/osx/WinSystemOSX.mm:CWinSystemOSX::OnMove`
- convention: videoscreen.monitor ships as OUTPUT_NAME_DEFAULT, meaning screen 0, and most profiles keep it. Rewriting it to a real screen name at window creation calls SetVideoResolution before the render system exists, leaving the GL viewport unset and the GUI black on first launch. | check: monitor selection treats Default as valid, not a stale name to resolve, and triggers no resolution change before InitRenderSystem | at: `xbmc/windowing/osx/WinSystemOSX.mm:CWinSystemOSX::SynchronizeCurrentMonitor`
- external: getmntinfo returns APFS implementation mounts (the Data volume, a duplicate System mount) that Disk Arbitration calls non-removable. Local drives are home, Desktop, /Volumes and /, minus mounts flagged MNT_DONTBROWSE or whose volume name does not resolve. | check: macOS storage enumeration filters MNT_DONTBROWSE and drops sources with an empty label | at: `xbmc/platform/darwin/osx/storage/OSXStorageProvider.mm:COSXStorageProvider::GetLocalDrives`
- external: tvOS gives apps no persistent file storage beyond a small NSUserDefaults store, and Kodi's home lives in Caches, which the OS can purge. CTVOSFile redirects only .xml files under userdata, and only plain local paths, not ones with a protocol, so databases, thumbnails and add-on files can vanish between launches. | check: tvOS state that must persist is userdata XML reached by a plain path; anything else is treated as disposable | at: `xbmc/platform/darwin/tvos/filesystem/TVOSFile.cpp:CTVOSFile::WantsFile`, `xbmc/filesystem/FileFactory.cpp:CFileFactory::CreateLoader`
- external: macOS and FreeBSD libc time conversion fails for dates before 1900, so pre-1900 and time-only CDateTime tests (a time-only value sits in 1601) are disabled there. Dates outside the 32-bit time_t range render as strings only where time_t is 64-bit. | check: date code going through time_t or libc conversion handles pre-1900 dates on macOS and dates outside the 32-bit range | at: `xbmc/platform/posix/XTimeUtils.cpp:KODI::TIME::SystemTimeToFileTime`
