- invariant: Kodi tries each built windowing in turn (Wayland, X11, GBM) unless --windowing names one, deleting a winsystem whose InitWindowSystem fails. A backend that registers global factories or state before it knows it can connect breaks the next one, e.g. Wayland on an X11 session with WAYLAND_DISPLAY set. | check: InitWindowSystem bails out before any global registration when the display server is unreachable, or undoes it on failure | at: `xbmc/application/Application.cpp:CApplication::CreateGUI`, `xbmc/windowing/wayland/WinSystemWayland.cpp:CWinSystemWayland::InitWindowSystem`
- scenario: GBM can start headless with COffScreenModeSetting: no CRTC, no active plane formats, FindGuiPlane skipped. When mesa has no GBM backend for the device CreateDevice fails, and the GLES 2 retry re-runs GBM init only when m_DRM is null. | check: GBM init changes work headless and reset both m_GBM and m_DRM on every failure | at: `xbmc/windowing/gbm/WinSystemGbm.cpp:CWinSystemGbm::InitWindowSystem`, `xbmc/windowing/gbm/WinSystemGbmEGLContext.cpp:CWinSystemGbmEGLContext::CreateNewWindow`
- external: GLES 2 is a live path: Kodi forces it on webOS 3 and 4, whose GPU drivers corrupt GUI icons under GLES 3, and GBM falls back to it on drivers without GLES 3 such as lima. | check: GLES renderer or shader changes still work on GLES 2 | at: `xbmc/rendering/gles/RenderSystemGLESWebOS.h:CRenderSystemGLESWebOS`, `xbmc/windowing/gbm/WinSystemGbmGLESContext.cpp:CWinSystemGbmGLESContext::InitWindowSystem`
- scenario: A DRM connector can expose an empty mode list; UpdateResolutions then registers the current mode as the only desktop resolution. | check: GBM resolution code works with zero connector modes and never indexes an empty list | at: `xbmc/windowing/gbm/WinSystemGbm.cpp:CWinSystemGbm::UpdateResolutions`
- external: amdgpu rejects an atomic commit that leaves an enabled CRTC without a primary plane. Under QUIRK_NEEDSPRIMARY Kodi picks only primary planes, never detaches an empty GUI plane, and leaves planes on other connectors alone. | check: changes that detach, disable or pick planes keep the QUIRK_NEEDSPRIMARY branches | at: `xbmc/windowing/gbm/drm/DRMUtils.cpp:CDRMUtils::OpenDrm`, `xbmc/windowing/gbm/drm/DRMAtomic.cpp:CDRMAtomic::DrmAtomicCommit`
- trap: On amdgpu, destroying the GBM surface removes a still-bound framebuffer and the kernel turns the CRTC off. After a surface rebuild (bit depth change for HDR) the next commit needs a full modeset, and the plane's cached format and modifier must come from the new front buffer. | check: code that recreates the GBM surface calls SetActive(true) and refreshes plane format and modifier before the next commit | at: `xbmc/windowing/gbm/WinSystemGbmEGLContext.cpp:CWinSystemGbmEGLContext::SetVideoOutput`
- convention: A DRM cursor plane is used for video or GUI only when the driver exposes INPUT_WIDTH/INPUT_HEIGHT limits; most drivers keep cursor planes tiny. | check: plane selection does not accept PLANE_TYPE_CURSOR planes on drivers without size hints | at: `xbmc/windowing/gbm/drm/DRMPlane.cpp:CDRMPlane::Check`
- invariant: Non-blocking atomic flips need triple buffering, but the DRM PRIME video layer returns a buffer to the pool once the next frame is ready. With a video plane active Kodi flips synchronously; a pending modeset also forces a blocking commit. | check: GBM changes keep async flips off on the video layer path, or direct-to-plane video tears | at: `xbmc/windowing/gbm/WinSystemGbmGLESContext.cpp:CWinSystemGbmGLESContext::PresentRender`, `xbmc/windowing/gbm/drm/DRMAtomic.cpp:CDRMAtomic::FlipPage`
- trap: After a GBM mode change the video thread waits for OnResetDisplay, but while the player starts PresentRender sees neither a rendered frame nor a video layer, so a reset check inside the render branch never fires and playback hangs. | check: pending reset or timer checks in a present path sit outside the something-was-rendered branch | at: `xbmc/windowing/gbm/WinSystemGbmGLESContext.cpp:CWinSystemGbmGLESContext::PresentRender`, `xbmc/windowing/gbm/WinSystemGbmGLContext.cpp:CWinSystemGbmGLContext::PresentRender`
- trap: OnLostDisplay and OnResetDisplay handlers can destroy their owner, which unregisters it from m_resources mid-loop; m_resourceSection is recursive, so the lock does not stop it. GBM iterates a copy and skips entries no longer registered; Android and tvOS range-for over m_resources directly. | check: any loop calling registered display resources iterates a snapshot and rechecks membership | at: `xbmc/windowing/gbm/WinSystemGbm.cpp:CWinSystemGbm::OnLostDevice`, `xbmc/windowing/android/WinSystemAndroid.cpp:CWinSystemAndroid::SetHdmiState`
- trap: CDRMUtils::GetResolutionInfo sets fPixelRatio 1.0 for every DRM mode, including the non-square 720x480 and 720x576 modes, and ApplyCalibrations replaces pixel ratio and overscan for any mode with a saved calibration matched by strMode. | check: a pixel ratio or overscan change accounts for saved calibrations overriding it, and SD modes are not assumed square | at: `xbmc/windowing/gbm/drm/DRMUtils.cpp:CDRMUtils::GetResolutionInfo`, `xbmc/settings/DisplaySettings.cpp:CDisplaySettings::ApplyCalibrations`
- external: wp_presentation's sync_output event is optional and a compositor may never send it. CVideoSyncWpPresentation takes its fps from the sync output refresh rate with no zero guard, and treats a zero MSC as one frame. | check: Wayland timing code handles a missing sync output rate and MSC, and prefers the refresh in the presented event | at: `xbmc/windowing/wayland/VideoSyncWpPresentation.cpp:CVideoSyncWpPresentation::Setup`
- trap: Unless the GL interface is glx, X11 first creates an EGL context and, on a non-Nvidia GPU only, keeps it when VAAPI registers, on Intel or when the interface is egl; otherwise, and always on Nvidia, it switches to GLX for VDPAU. A static_cast of m_pGLContext to CGLContextEGL reads garbage on GLX. | check: X11 code tests the context type with dynamic_cast and handles EGL_NO_DISPLAY | at: `xbmc/windowing/X11/WinSystemX11GLContext.cpp:CWinSystemX11GLContext::RefreshGLContext`
- external: libdbus is thread safe only after dbus_threads_init_default(), and Kodi calls dbus from several threads (power management, UDisks, logind). CPlatformPosix::InitStageOne calls it first. | check: new dbus users never run before platform init stage one, e.g. from static initializers | at: `xbmc/platform/posix/PlatformPosix.cpp:CPlatformPosix::InitStageOne`
- external: On webOS the Starfish pipeline outputs audio itself and needs the ALSA device; if ActiveAE keeps it open, even writing silence, webOS 26 stutters with broken pipe errors. Kodi yields it with IAE::YieldDevice before the pipeline loads and reclaims it on pause and after UNLOADCOMPLETED, or in the destructor if that event never comes. | check: yield and reclaim stay paired and idempotent, and the device is never returned before the pipeline unloads | at: `xbmc/cores/VideoPlayer/MediaPipelineWebOS.cpp:CMediaPipelineWebOS::RequestAudioDevice`
- scenario: CWinSystemBase::Minimize returns false and only GBM and wasm keep it, so the Minimize builtin does nothing there. | check: features that rely on Minimize handle a false return on GBM and wasm | at: `xbmc/windowing/WinSystem.h:CWinSystemBase::Minimize`
