- convention: The main thread runs input, windows, rendering and every CApplicationMessenger message; GUI entry points callable from other threads check IsProcessThread and marshal with SendMsg or SendThreadMessage. CTimeUtils::GetFrameTime advances only in CApplication::Render, skipped while GetRenderGUI() is false. | check: a GUI change reachable off the main thread without marshalling; a worker timing on GetFrameTime | at: `xbmc/guilib/GUIWindowManager.cpp:CGUIWindowManager::ActivateWindow`
- convention: CJob::DoWork and OnJobComplete run on the job's worker, CTimer callbacks on the timer's own thread, IAnnouncer::Announce later on the Announce thread. | check: a callback touching GUI state or assuming the main or queuing thread | at: `xbmc/jobs/JobManager.cpp:CJobManager::OnJobComplete`
- invariant: GuiLock releases the GIL (DelayedCallOpen), then takes m_frameMoveGuard, then the gfx lock. The main thread takes the GIL in CPythonInvoker::stop with m_frameMoveGuard held, so a binding waiting on the main thread or the gfx lock with the GIL held can deadlock. | check: a binding that blocks or takes the gfx lock outside DelayedCallGuard or GuiLock | at: `xbmc/interfaces/legacy/AddonUtils.cpp:GuiLock::GuiLock`
- invariant: The main thread holds m_frameMoveGuard from CreateGUI until Stop, releasing it only at the FrameMove door (while a GuiLock caller waits, gfx dropped too), around CScriptInvocationManager::Process, and around ClosePlayer in StopPlaying. | check: GuiLock taken off the main thread under a lock the main thread takes before the door; GuiLock per item in a loop | at: `xbmc/application/Application.cpp:CApplication::FrameMove`
- invariant: SendMsg off the main thread waits with no timeout, dropping only the gfx lock; on the main thread it runs inline. After CApplicationMessenger::Stop it returns -1 unqueued; Cleanup wakes queued waiters unrun. | check: a SendMsg caller holding GuiLock or another lock the main thread takes; a caller assuming the message ran | at: `xbmc/messaging/ApplicationMessenger.cpp:CApplicationMessenger::SendMsg`
- trap: Busy-dialog waits and modal loops on the main thread call ProcessRenderLoop, so messages, actions and builtins run inside the wait and can re-enter the caller or free its windows and controls. | check: caller state consistent before the wait; GUI pointers revalidated after it | at: `xbmc/guilib/GUIWindowManager.cpp:CGUIWindowManager::ProcessRenderLoop`
- invariant: GUI info getters run every frame on the main thread under the gfx lock, so I/O, add-on calls and locks a slow thread holds belong on a worker that caches. | check: a getter doing I/O or taking a lock a slow thread holds | at: `xbmc/pvr/guilib/guiinfo/PVRGUIInfo.cpp:CPVRGUIInfo::Process`
- trap: CCriticalSection is recursive, so a callback on the owning thread can change a container mid-walk. CSingleExit releases every level until scope end; ConditionVariable::wait releases one, so a section held twice blocks the notifier. | check: callbacks mid-iteration without a snapshot; pointers kept across CSingleExit; a wait with its section held twice | at: `xbmc/threads/Condition.h:XbmcThreads::ConditionVariable::wait`
- invariant: Never wait on a thread while holding a lock its code takes; StopThread(true), CTimer::Stop(true) or Restart, and destructors stopping a worker block until it returns. The main thread waits on a thread that may wait on it (SendMsg, GuiLock, gfx) only with gfx and m_frameMoveGuard dropped by CSingleExit, or while pumping ProcessMessages. | check: Stop, Unload, a join or CEvent::Wait under a lock the worker takes, or on the main thread for a worker that marshals to it | at: `xbmc/pvr/PVRManager.cpp:CPVRManager::Start`
- invariant: Lock order is gfx, then component locks: the main thread takes component locks with gfx held, so a non-main thread holding a component lock deadlocks taking gfx or GuiLock. Locks ordered before gfx are taken after CSingleExit on gfx, as CRenderManager::Render does for m_statelock. | check: gfx or GuiLock taken inside a component lock off the main thread | at: `xbmc/cores/VideoPlayer/VideoRenderers/RenderManager.cpp:CRenderManager::Render`
- trap: CSharedSection admits readers while a writer waits, so steady readers starve it, and lock() on a thread holding it shared waits forever. A default CEvent auto-resets: a Set with no waiter stays pending for the next Wait, repeated Sets collapse into one, and one Set releases every current waiter. | check: a shared holder reaching lock() on the same section; code counting Sets as wakeups | at: `xbmc/threads/SharedSection.h:CSharedSection::lock`
- trap [22]: DoAnnounce holds m_announcersCritSection across every call, so AddAnnouncer or RemoveAnnouncer from another thread blocks until the dispatch ends, and one removed during a call is still called from the copy. | check: an announcer waiting on a lock or thread (SendMsg, closing a window) whose holder adds or removes an announcer | at: `xbmc/interfaces/AnnouncementManager.cpp:CAnnouncementManager::DoAnnounce`
- invariant [23+]: DoAnnounce drops m_announcersCritSection for each call and rechecks membership; RemoveAnnouncer off the Announce thread waits for that listener's running call. | check: an announcer waiting on a lock or thread (SendMsg) whose holder removes that announcer | at: `xbmc/interfaces/AnnouncementManager.cpp:CAnnouncementManager::DoAnnounce`
- trap: AddJob deletes the job, returning 0 once the manager stopped, or the match's id after adding the callback to a same-priority queued job or any running job that Equals it. CancelJob on a running job only drops callbacks: DoWork runs on, a job already in OnJobComplete still calls back, and ShouldCancel turns true, as for any job without a callback. | check: the job used after AddJob; an Equals missing an input; an owner freed while its job runs | at: `xbmc/jobs/JobManager.cpp:CJobManager::AddJob`
- invariant: A job stays busy until its OnJobComplete callbacks return; LOW, NORMAL and HIGH start only while all non-pausable busy jobs, DEDICATED included, number under 3, 4 and 5. CancelJobs (CApplication::Stop, messenger already stopped) calls running jobs' OnJobAbort under the manager lock and spins until every worker ends its current DoWork. PRIORITY_LOW_PAUSABLE jobs stay queued while video, pictures or a fullscreen game show. | check: a job callback that blocks or waits on another thread; a DoWork ignoring ShouldCancel; a pausable job awaited from playback | at: `xbmc/jobs/JobManager.cpp:CJobManager::CancelJobs`
- trap: CThread::Create while the old thread runs calls exit(1), and StopThread from that thread never joins, so a Create from its own Process kills Kodi and CTimer::Restart from its callback stops the timer. | check: every Start, restart or wake path joins the old thread first from outside it; timer callbacks use RestartAsync | at: `xbmc/threads/Thread.cpp:CThread::Create`
- trap: ~CThread stops the thread after the subclass is destroyed, so Process can use freed members and a StopThread override is skipped. StopThread waits without limit; only m_bStop, AbortableWait and Sleep over 10 ms see it. | check: subclass destructors stop the thread first; Process loops poll m_bStop or wait abortably | at: `xbmc/threads/Thread.cpp:CThread::~CThread`
