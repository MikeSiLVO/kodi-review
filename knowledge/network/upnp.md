- trap: A Platinum control point reply carries only the userdata pointer it was sent with, so actions sharing one userdata let a late reply (after a timeout, or for an action already retired) release whichever wait is outstanding with the wrong status. - trap [22]: CUPnPPlayer passes one shared delegate as userdata for every renderer action, and its SetAVTransportURI, Play and Stop results all set one event, so a late reply can complete a later action's wait. | check: a backport of renderer action changes does not assume master's per-action delegates | at: `xbmc/network/upnp/UPnPPlayer.cpp:CUPnPPlayer::PlayFile`
