- convention: CGUIAction::ExecuteActions evaluates every action's condition first, then runs all that passed in order, not first match; integer entries (navigation ids) are skipped. Each action's `$INFO` is expanded just before it runs, so a later SetProperty sees properties set by earlier ones in the same list, but the conditions do not. | check: batching, deferring or pre-resolving actions keeps conditions snapshotted up front and labels expanded per action, which skins use for read-modify-write property chains | at: `xbmc/guilib/GUIAction.cpp:CGUIAction::ExecuteActions`, `xbmc/application/Application.cpp:CApplication::ExecuteXBMCAction`
- trap: ExecuteXBMCAction expands an action's labels with the list item only when the action came from a container item; otherwise it uses INFO::DEFAULT_CONTEXT and no item, so a bare ListItem.* in a button's onclick or a window's onload does not read the item the user was on. | check: changes to how actions carry items keep the clicked item for item actions and do not assume a bare ListItem elsewhere resolves to a given container | at: `xbmc/application/Application.cpp:CApplication::ExecuteXBMCAction`
- convention: CUtil::SplitParams splits builtin arguments on commas outside double quotes and parentheses, trims unquoted whitespace, strips outer quotes and the quotes of `name="value"`, and collapses `\\` to `\` and `\"` to `"` anywhere, so an unquoted `\\server\share` arrives as `\server\share` and a comma produced by `$INFO` expansion adds an argument. RunScript passes the result as sys.argv. | check: SplitParams changes keep the quote, escape, nesting and name="value" rules | at: `xbmc/Util.cpp:CUtil::SplitParams`
- convention: A path or label put into a builtin string goes through StringUtils::Paramify, which quotes it and escapes backslashes and quotes; CExecString::Build joins its params unquoted, so callers Paramify each one. | check: a builtin built from data (titles, paths, conditions) Paramifies every value so commas, quotes and trailing backslashes survive | at: `xbmc/utils/StringUtils.cpp:StringUtils::Paramify`, `xbmc/utils/ExecString.cpp:CExecString::Build`
- scenario: Builtin strings carry spaces around values, nested calls `fun(fun2(p1,p2),p3)`, quoted values with commas, escaped quotes, quotes opening mid-token, `name=value1, value2`, an empty quoted argument `SetProperty(Foo,"")`, a `)` inside quotes, and Windows paths with doubled or trailing backslashes such as `"C:\test\foo\"`. | check: a parse or build change is tested with a quoted path ending in a backslash, an empty quoted argument and a quoted `)` | at: `xbmc/test/TestUtil.cpp:TestUtilSplitParams`, `xbmc/utils/test/TestExecString.cpp:TestExecString`
