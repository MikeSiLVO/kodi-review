- trap: `special://videoplaylists/` and `musicplaylists/` translate to a `multipath://` over the video or music and the mixed playlist folders with the rest appended, so `special://videoplaylists/X.xsp` is `multipath://<a>/<b>/X.xsp`. CFile Open, Exists and Stat try X in each member, but a directory listing reads X.xsp as a third member, and the translated path is useless outside the VFS. | check: a path built under these aliases is opened through CFile, or uses the resolved child path a listing returns | at: `xbmc/filesystem/SpecialProtocol.cpp:CSpecialProtocol::TranslatePath`, `xbmc/filesystem/MultiPathDirectory.cpp:CMultiPathDirectory::GetPaths`
- trap: CXBMCTinyXML::SaveFile opens the target with OpenForWrite(overwrite), which truncates it, and only then prints and writes the document, so the file is empty while it serializes and a concurrent reader parses nothing. | check: an XML file one thread saves while another may read (settings, sources, favourites) is not treated as an atomic write | at: `xbmc/utils/XBMCTinyXML.cpp:CXBMCTinyXML::SaveFile`
- trap: CFile::Rename replaces an existing target on POSIX (rename(), and its EXDEV copy-then-delete fallback overwrites) but fails on Windows, where MoveFileExW gets only MOVEFILE_COPY_ALLOWED; write-temp-then-rename is not portable through the VFS. | check: a rename onto an existing path (atomic save, cache swap, backup rotation) handles the Windows failure | at: `xbmc/platform/win32/filesystem/Win32File.cpp:CWin32File::Rename`, `xbmc/platform/posix/filesystem/PosixFile.cpp:CPosixFile::Rename`
- convention: IDirectory defaults to CacheType::ONCE, which the directory cache serves back only to a fetch passing DIR_FLAG_READ_CACHE (art and thumb lookups); any other fetch clears the entry and refetches. CPluginDirectory keeps the default, so every plugin listing runs the plugin again. | check: a claim that a listing is cached names CacheType::ALWAYS or a READ_CACHE caller | at: `xbmc/filesystem/DirectoryCache.cpp:CDirectoryCache::GetDirectory`, `xbmc/filesystem/IDirectory.h:IDirectory::GetCacheType`
- convention: The directory cache keys on the path without URL options or trailing slash, so `ftp://host/dir`, `dir/`, `dir/?a=1` and `dir/?b=2` share one entry; clearing a file clears its directory, and clearing sub-paths must spare siblings that share a prefix. | check: a new cache key derived from a path normalizes trailing slash and options the same way | at: `xbmc/filesystem/DirectoryCache.cpp:CDirectoryCache::ClearSubPaths`
- convention: CDirectory::GetDirectory drops items marked `file:hidden` unless filelists.showhidden or DIR_FLAG_GET_HIDDEN is set, and the POSIX, Win32, SMB and NFS listings mark every dot-prefixed name hidden, so without either a listing never returns `.nomedia`. | check: code looking for a dotfile marker uses an exists check or DIR_FLAG_GET_HIDDEN | at: `xbmc/filesystem/Directory.cpp:CDirectory::GetDirectory`, `xbmc/InfoScanner.cpp:CInfoScanner::HasNoMedia`
- scenario: Zip inputs include a corrupted archive, extended local headers (sizes after the data), zip64 listings and a file over 4 GiB inside zip64. Entry names `..`, `../x`, `..\x`, `a/../x`, `a\..\x` are traversal; `...`, `..x`, `x..`, `a..b` are not. | check: zip sizes and offsets stay 64-bit, a corrupt archive fails the listing cleanly, and traversal checks cover both slash directions without catching ordinary dots | at: `xbmc/filesystem/ZipManager.cpp:CZipManager::GetZipList`
- scenario: CFileCache sources can fail a seek, return a wrong positive position, be asked to seek past the end, or hit EOF after a completed seek, which must not replay that seek. | check: a failed or lying seek leaves the read position unchanged and later reads fail promptly | at: `xbmc/filesystem/FileCache.cpp:CFileCache::Seek`
- scenario: A drive path can hold one disc, then another; Blu-ray cache entries for that path are dropped when a different disc appears. Removable Blu-ray paths look like `bluray://removable%3a%2f%2fsometitle_<40 hex>%00%cc/BDMV/index.bdmv`; Resolve maps them onto the item's drive path, `index.bdmv` to `E:\BDMV\index.bdmv` and a playlist to `bluray://E%3a%5c/BDMV/PLAYLIST/00800.mpls`. | check: anything cached by drive path is invalidated when the disc changes | at: `xbmc/filesystem/BlurayDiscCache.cpp:CBlurayDiscCache::CheckDisc`
- scenario: Playlist inputs: ASX with mixed-case elements (`<ENTRY><REF HREF=...>`) and unknown children; B4S `file:C:\Test Path\...` and `file:/Users/...`; WPL with UNC `\\server\vol\...` and bare relative names; XSPF with remote URLs, relative paths, `file:///C:/...`, percent-encoded `'`, `,` and `&`, `&#146;` in titles (a C1 control, not a quote), an empty `location` and a track without one; PXML with Cyrillic names. A remote `.m3u8` is HLS, not a playlist; `.xsp` is a smart playlist. | check: playlist loading resolves relative entries against the playlist's folder and survives Windows or UNC entries on other platforms, empty locations and a remote m3u8 | at: `xbmc/playlists/PlayListFactory.cpp:CPlayListFactory::IsPlaylist`
- trap: Probing an optical disc takes seconds, while GUI labels read disc details every frame under m_muReadingMedia. CDetectDVDMedia serializes detection with m_muDetect, takes m_muReadingMedia only to publish label, path and CCdInfo, returns label and path by value and hands out CCdInfo as shared_ptr. | check: storage code never returns a reference or raw pointer to lock-guarded state and never holds a lock readers need across slow device I/O | at: `xbmc/storage/DetectDVDType.cpp:CDetectDVDMedia::DetectMediaType`, `xbmc/storage/DetectDVDType.cpp:CDetectDVDMedia::GetCdInfo`
- invariant: Disc info labels and IsDiscInDrive run every GUI frame, so CMediaManager::GetDriveStatus caches each drive's state until expiry or a storage or tray event, and queries the drive outside the cache lock because a spinning-up drive can block for seconds. | check: a platform query reachable from info labels or visibility conditions is cached and never blocks the main thread on device I/O | at: `xbmc/storage/MediaManager.cpp:CMediaManager::GetDriveStatus`
- external: FreeBSD's /tmp is often a RAM disk too small for archive contents extracted through CFile, so Kodi's POSIX temp directory is /var/tmp/ there and /tmp/ elsewhere. | check: code writing large temporary files uses the platform temp path, not a hardcoded /tmp | at: `xbmc/platform/posix/Filesystem.cpp:temp_directory_path`
