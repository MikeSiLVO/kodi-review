- convention: ActiveAESink treats AddPackets returning 0 as full and sleeps half a period before retrying; a fifth 0 within one packet, or any value above the frames offered (sinks use INT_MAX), sets the sink error state, which reopens the sink, so a sink in a silent fallback must report data consumed. | check: sinks return 0, a count up to the request, or INT_MAX only on real failure | at: `xbmc/cores/AudioEngine/Engines/ActiveAE/ActiveAESink.cpp:CActiveAESink::OutputSamples`
- external: In RAW mode the Android AudioTrack sink opens a test track per encoding and lists only what the firmware accepts; EAC3 works on some boxes and not others. A device taking EAC3 but not AC3 gets AC3 tagged as EAC3, and TrueHD needs 192 kHz listed. | check: Android passthrough capability comes from the probe, not from the API constant, and the AC3-as-EAC3 path still works | at: `xbmc/cores/AudioEngine/Sinks/AESinkAUDIOTRACK.cpp:CAESinkAUDIOTRACK::UpdateAvailablePassthroughCapabilities`
- external: AudioTrack.getPlaybackHeadPosition is a wrapping 32-bit counter returned as signed; Kodi reads it unsigned and extends it to 64 bits. getLatency is missing on some devices and unused for RAW, where getTimestamp is trusted only under 50 ms old. | check: Android delay math keeps the head position unsigned 32-bit and handles getLatency returning -1 | at: `xbmc/cores/AudioEngine/Sinks/AESinkAUDIOTRACK.cpp:CAESinkAUDIOTRACK::GetDelay`
- scenario: Some Android devices mishandle AudioTrack pause plus flush, so a passthrough track opened right after a seek fails; the sink waits 200 ms and retries once; a failed PCM open retries with a 5.1, then a stereo channel mask. | check: AudioTrack open or teardown changes keep the delayed passthrough retry and the PCM 5.1 and stereo fallbacks | at: `xbmc/cores/AudioEngine/Sinks/AESinkAUDIOTRACK.cpp:CAESinkAUDIOTRACK::Initialize`
- external: HDMI 1.x (CEA-861-D) defines 7.1 as back plus back-left/right-of-center, not side plus back; the ALSA sink builds that alternate layout when matching a channel map. | check: HDMI channel-map changes keep the CEA-861 7.1 mapping, or rear and side pairs swap | at: `xbmc/cores/AudioEngine/Sinks/AESinkALSA.cpp:CAESinkALSA::GetAlternateLayoutForm`
- external: ELD detection can fail for connected HDMI sinks on Intel, Nvidia and AMD (fglrx), so missing ELD is only logged and ELD codecs are ignored: HDMI devices always get AC3, EAC3, DTS, DTS-HD, DTS-HD MA and TrueHD passthrough types. | check: Linux device listing and passthrough codecs are never gated on ELD contents | at: `xbmc/cores/AudioEngine/Sinks/AESinkALSA.cpp:CAESinkALSA::EnumerateDevice`
- trap: After an ALSA write error the PCM stays broken until snd_pcm_prepare (or resume on ESTRPIPE); handling only EPIPE and ESTRPIPE leaves long passthrough playback dead after other errors. | check: every error branch in an ALSA write path leaves the PCM prepared or reopened, not just logged | at: `xbmc/cores/AudioEngine/Sinks/AESinkALSA.cpp:CAESinkALSA::HandleError`
- scenario: ALSA "default" is always listed. A stereo default switches to the "@" form so surroundXX mangling works, but a default that does multichannel itself, as with PulseAudio behind it, skips the mangling. | check: enumeration changes keep "default" listed and never mangle a multichannel default | at: `xbmc/cores/AudioEngine/Sinks/AESinkALSA.cpp:CAESinkALSA::EnumerateDevicesEx`
- convention: Linux picks the backend at startup from --audio-backend (alsa+pulseaudio registers both), else takes the first of PulseAudio, PipeWire, ALSA, sndio that registers. In that order a Pulse server named "pipewire" is PipeWire's Pulse layer, so the Pulse sink refuses it for native PipeWire; an explicit pulseaudio accepts it. | check: Linux sink changes hold under real PulseAudio, native PipeWire and PipeWire's Pulse layer | at: `xbmc/platform/linux/PlatformLinux.cpp:CPlatformLinux::InitStageOne`, `xbmc/cores/AudioEngine/Sinks/AESinkPULSE.cpp:CDriverMonitor::Start`
- external: The Pulse sink sends passthrough only as IEC 61937 in a 2-channel stream, cannot take planar formats (falls back to float), and clamps rates to 5512 Hz to 384 kHz. | check: Pulse sink changes offer no RAW or multichannel passthrough and keep the planar fallback | at: `xbmc/cores/AudioEngine/Sinks/AESinkPULSE.cpp:CAESinkPULSE::Initialize`
- external: On webOS ALSA is only a shim to PulseAudio and from webOS 26 its config is unreadable, so webOS builds force PulseAudio and exclude ALSA. | check: webOS audio changes go in the Pulse sink path and do not bring ALSA back | at: `cmake/platform/linux/webos.cmake`
- external: The PipeWire sink offers passthrough only for the IEC958 codecs the node advertises (set by the user in PipeWire) and skips nodes until PipeWire fills their info or when they lack channel info. A 2-channel node without TrueHD or DTS-HD MA is typed IEC958, which caps its PCM at stereo. | check: enumeration changes handle nodes seen before their info and the IEC958 stereo side effect | at: `xbmc/cores/AudioEngine/Sinks/pipewire/AESinkPipewire.cpp:CAESinkPipewire::EnumerateDevicesEx`
- external: WASAPI always opens exclusive and event-driven, with a buffer that is a multiple of the device period. Some drivers reject it, so it retries one period smaller on size, period or out-of-memory errors and rebuilds at the driver's size when not aligned. | check: WASAPI open changes keep the retry loop and assume neither shared mode nor first-size success | at: `xbmc/cores/AudioEngine/Sinks/AESinkWASAPI.cpp:CAESinkWASAPI::InitializeExclusive`
- external: Windows sinks probe float, S24NE4MSB, S32, packed 24-bit, then S16; 24-in-32 goes before S32 because some IEC958 devices claim S32 but fail with it. | check: the Windows probe order keeps S24NE4MSB ahead of S32 | at: `xbmc/cores/AudioEngine/Sinks/windows/AESinkFactoryWin.h:testFormats`
- external: XAudio2 Stop and FlushSourceBuffers return before queued buffers are released, so the sink waits on its buffer-end event before destroying the voice. Some devices fail with E_NOINTERFACE even for the default id, so the fallback open passes a null device id. | check: XAudio teardown waits for buffer release, and fallback opens pass a null id | at: `xbmc/cores/AudioEngine/Sinks/AESinkXAudio.cpp:CAESinkXAudio::Deinitialize`
- external: macOS passthrough writes IEC 61937 bursts as S16 and converts them to float in the render callback, so CoreAudio's float-to-S16 conversion restores the exact bits; any gain, mix or dither there corrupts the bitstream. | check: render callback changes leave the bitstream path bit-exact | at: `xbmc/cores/AudioEngine/Sinks/AESinkDARWINOSX.cpp:CAESinkDARWINOSX::renderCallback`
- external: tvOS reports the user's audio setting as AVAudioSession.maximumOutputNumberOfChannels (2, 6 or 8). The sink lists AC3, EAC3 and DTS, but passthrough only happens on an HDMI route; otherwise RAW falls back to float PCM. | check: tvOS changes read the channel limit from the session and do not assume passthrough from listed RAW formats | at: `xbmc/cores/AudioEngine/Sinks/AESinkDARWINTVOS.mm:CAESinkDARWINTVOS::Initialize`
